# sdf-plan v0.2.8

Release date: 2026-02-16

## Highlights

- Added wildcard/prefix tool classification (for example `filesystem.*`) with deterministic precedence.
- Added strict `tool_args_validator` support for host-enforced deep payload validation.
- Tightened strict hashing behavior so non-JSON-native values are rejected in strict paths.
- Updated docs with replay protection guidance using token `jti` and clear adapter-vs-legacy migration guidance.
- Added CI guard coverage for `jti`, strict scope enforcement, and legacy/adapters import clarity.

## Security and Correctness

- Confirmation tokens continue to include signed `jti`, expiry, scope, tool, and args-hash binding.
- Strict mode now enforces stronger invariants:
  - write operations require `ctx.workspace_id`
  - strict hashing rejects non-JSON-native values
  - optional `tool_args_validator` can hard-fail bad tool payloads

## Strict Mode Callout

This release introduces a behavior change in strict mode only:

- Missing workspace scope for write tools now blocks with `STRICT_SCOPE_REQUIRED`.
- Invalid strict validator payloads block with `STRICT_ARGS_VALIDATION_FAILED`.

Non-strict mode behavior remains backward compatible.

## Migration Guidance

1. Keep current non-strict mode in production.
2. Enable strict mode in staging first.
3. Ensure every write path passes `GateContext(workspace_id=...)`.
4. Add a replay store keyed by `workspace_id + jti`.
5. Add `tool_args_validator` for high-risk tools.
